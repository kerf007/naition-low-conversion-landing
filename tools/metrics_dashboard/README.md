# Локальная панель экспериментов

Из корня репозитория:

```sh
python3 -B tools/metrics_dashboard/serve.py
```

Открыть **http://127.0.0.1:8787/**. Для другого порта: `--port 8788`.

Зависимости: Python 3.10+ и современный браузер. Установка пакетов не нужна. Сервер слушает только 127.0.0.1 и отдаёт разрешённые файлы интерфейса и агрегаты `/api/data`; весь репозиторий не раздаётся. Остановка — Ctrl+C в терминале сервера.

## Возможности

- 12 основных исторических прогонов, включая новый эксперимент 3 900 ₽ на 501 серверный визит. Ранние пилоты и неполные прогоны не включены в каталог.
- Выбор любого прогона и контроля; выбор сохраняется в адресе страницы.
- Серверная конверсия, 95% интервалы Уилсона, разница с контролем и двусторонний точный тест Фишера.
- Клиентская воронка, переход к вводу, потери после CTA, ошибки и доступные медианы времени.
- Сопоставление счётчиков сервера и трекера, явное обозначение отсутствующей телеметрии.
- Поиск в таблице и экспорт агрегатов в JSON.

## Источники и обновление

Это просмотр сохранённых результатов, а не мониторинг в реальном времени. Кнопка **«Обновить из файлов»** перечитывает локальные отчёты. Она не обращается к лендингу, не запускает симулятор и не скачивает новый прогон.

Каталог `RUNS` находится в `data.py`. Для нового эксперимента:

1. Сохранить экспорт и агрегированный отчёт в принятом формате `reports/behavior-…json`.
2. Добавить запись в `RUNS`: идентификатор, название, короткая подпись, коммит, дата, серверные визиты/заявки, цена, поля, описание и имя JSON-отчёта.
3. При необходимости поменять `default_run` и `default_control` в `build_data`.
4. Перезапустить сервер и обновить страницу. Изменения существующих JSON-отчётов видны по кнопке без перезапуска.

Поддерживаются агрегаты `events/details/cohorts` и сводки с блоком `current`. Для двух ранних прогонов сведения перенесены из отчётов, ссылки на них приведены в комментариях к `data.py`. Исходный результат 15/503 — исторический пакет лидерборда, без клиентской воронки.

На клиент передаётся только явно собранная схема агрегатов. Данные отдельных посетителей и контактные значения заявок не читаются этим интерфейсом. Поле `source` содержит имя отчёта, а не его исходное содержимое.

## Интерпретация

### Диагностика до ввода

Если после Redeploy приходят события старой вкладки, экспорт разбивается по `trackerVersion`, `uiVersion` и `experimentId`. Такие группы показаны отдельно, их пропуски событий не приписываются новому эксперименту.

Новый раздел читает `data/visits-*/diagnostics.json` — сохранённые ответы `diagnostics.php?format=visits`. Кнопка обновления перечитывает их без перезапуска. Это отдельные диагностические экспорты; они не приписываются историческим прогонам по совпадению цены или даты. В интерфейс передаются только агрегированные категории и времена, без хронологии отдельных UUID.

Проверка классификатора:

```sh
python3 -B -m unittest discover -s tools/metrics_dashboard -p test_diagnostics.py
```

Полный план и ограничения: [pre-input-instrumentation-2026-10-23.md](../../reports/pre-input-instrumentation-2026-10-23.md).

### Основные метрики

Общая конверсия использует серверные визиты и заявки. Воронка использует клиентские пересечения этапов; её знаменатель может отличаться. В последнем прогоне 22/103, в контроле 30/102; после отделения старой вкладки серверные и клиентские счётчики совпадают. В историческом повторе лучшей версии сервер показывает 59/201, клиент — 59/200. Не следует делить клиентские события на серверный знаменатель без оговорки.

Интервал разницы рассчитан методом Ньюкомба на основе интервалов Уилсона. Значения p — без поправки на многократные сравнения; прогоны последовательные, независимость визитов не установлена. Интерфейс не объявляет причинный эффект или победителя автоматически. Для одного и того же прогона статистическое сравнение отключено.

Воронка предполагает вложенность этапов в наших зафиксированных прогонах; сборщик проверяет неравенства численностей. Для новых сценариев, где заявки отправляются без CTA, потребуется отдельная ветка воронки, а не подстановка таких событий в существующую.

## Проверено

390, 768 и 1440 px без горизонтального переполнения страницы; широкие график и таблица прокручиваются внутри своих блоков. Проверены выбор прогонов, отсутствие телеметрии, расхождение 55/56 заявок, сравнение с самим собой, поиск, обновление и скачивание JSON. Проверены расчёты Фишера на известных результатах, граничные значения Уилсона и отсутствие доступа к файлам вне разрешённого списка.
