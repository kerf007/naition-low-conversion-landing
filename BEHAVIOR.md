# Изучение поведения симулятора

`js/main.js` отправляет обезличенные события в `behavior.php`. Значения полей формы,
телефоны, почта, IP-адреса и user agent не сохраняются. Случайный идентификатор
создаётся заново для каждой загрузки страницы и нужен только для подсчёта уникальных
просмотров каждого шага.

Контрольная точка до установки трекера: 200 визитов и 9 заявок (4,5%) по результату
панели, сообщённому владельцем проекта. Поведение в этом прогоне уже не восстановить.

## Как получить данные

1. Сделать Redeploy и запустить симулятор с выбранным числом визитов.
2. После завершения открыть `https://kerf007.naition.sortedmap.ru/behavior.php` и сохранить JSON до следующего Redeploy.
3. Сравнить `page_view` с числом визитов симулятора, а `form_success` с числом заявок в `api/export.php` или лидерборде. Расхождение показывает, что часть событий не дошла или заявка была создана без клиентского сценария.

База событий находится вне веб-каталога во временном хранилище контейнера. Она
сбрасывается при замене контейнера, в том числе при Redeploy. Отчёт содержит только
агрегаты: `events` показывает число событий (`hits`) и число просмотров с событием
(`sessions`), `details` разбивает события по заранее заданным категориям.

## Что смотреть в отчёте

| Этап | События | Вопрос |
| --- | --- | --- |
| Попадание на страницу | `page_view` по типу экрана | Исполняется ли клиентский код у всех визитов? |
| Видимость и прокрутка | `cta_view`, `program_view`, `pricing_view`, `form_view`, `scroll_depth` | Какие части страницы были в поле зрения? Видимость фиксируется после 0,5 секунды при показе хотя бы половины элемента; глубина прокрутки означает достижение точки, а не чтение текста. |
| Намерение | `cta_click`, `pricing_link_click` | Какая кнопка приводит к форме: в первом экране или в тарифах? |
| Форма | `form_start`, `field_focus`, `form_submit_click`, `form_invalid` | Доходят ли до ввода данных и на каком поле возникает ошибка браузерной проверки? `form_start` фиксируется при первом вводе. |
| Исход | `form_submit`, `form_success`, `form_error`, `form_abandon` | Теряются ли заявки до отправки или после ответа сервера? |
| Время | `page_exit` | Сколько длился просмотр; событие может отсутствовать при резком закрытии браузера. |

Для долей воронки используйте `sessions`, а не `hits`: один просмотр может несколько
раз нажать кнопку или ошибиться при заполнении. События показывают действия, но сами
по себе не объясняют мотив бота. Следующую правку стоит выбирать по самому большому
падению между этапами и проверять отдельным прогоном симулятора.
