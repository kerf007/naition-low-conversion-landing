# Изучение поведения симулятора

`js/main.js` отправляет события в `behavior.php`. В базе поведения не сохраняются
значения полей формы, телефоны, почта, IP-адреса и user agent. Случайный идентификатор создаётся
заново для каждой загрузки страницы и связывает события только внутри визита.

Контрольная точка до установки трекера: 200 визитов и 9 заявок (4,5%) по результату
панели, сообщённому владельцем проекта. Поведение в этом прогоне уже не восстановить.

## Как получить данные

1. Сделать Redeploy и запустить симулятор с выбранным числом визитов.
2. После завершения сохранить два JSON до следующего Redeploy:
   - `https://kerf007.naition.sortedmap.ru/behavior.php` — общая воронка;
   - `https://kerf007.naition.sortedmap.ru/behavior.php?format=visits` — траектории отдельных визитов.
3. Разложить второй файл для `webvisor-conversion-analysis`:

   ```bash
   node scripts/split-behavior-visits.mjs visits.json data/webvisor-visits
   ```

4. Сравнить `page_view` с числом визитов симулятора, а `form_success` с числом заявок в `api/export.php` или лидерборде. Расхождение показывает, что часть событий не дошла или заявка была создана без клиентского сценария.

База событий находится вне веб-каталога во временном хранилище контейнера. Она
сбрасывается при замене контейнера, в том числе при Redeploy. Отчёт содержит только
агрегаты: `events` показывает число событий (`hits`) и число просмотров с событием
(`sessions`), `details` разбивает события по заранее заданным категориям, а `cohorts`
считает просмотры, в которых встретились оба шага воронки. Второй экспорт содержит
`visitId`, `pageHeight`, `viewportHeight`, `maxScrollY`, `scrollDepthPct`,
`durationSec`, `clicks`, `formEvents`, `inputNodes`, `scrollEvents` и полную
хронологию `events`. `ended: false` означает, что событие закрытия страницы не дошло:
в таком случае длительность и глубина — нижние оценки. Координаты курсора,
содержимое полей, полный URL, реферер и произвольные CSS-селекторы не собираются.
Каждый шаг содержит относительное время визита в миллисекундах; глубина прокрутки
берётся как максимум по полученным событиям.
`section_enter` нумерует секции в порядке DOM: `s1` — `header.hero`, далее
`main > section` сверху вниз. Для скилла эту карту нужно сверить с DOM после прогона.

## Что смотреть в отчёте

| Этап | События | Вопрос |
| --- | --- | --- |
| Попадание на страницу | `page_view` по типу экрана | Исполняется ли клиентский код у всех визитов? |
| Видимость и прокрутка | `cta_view`, `program_view`, `pricing_view`, `form_view`, `form_field_view`, `form_submit_view`, `scroll_depth`, `scroll_checkpoint`, `section_enter` | Какие части страницы были в поле зрения? `form_view` означает заголовок, а два следующих события — первое поле и кнопку. Видимость фиксируется после 0,5 секунды при показе хотя бы половины элемента; прокрутка и переходы между секциями означают достижение точки, а не чтение текста. |
| Намерение | `cta_click`, `pricing_link_click`, `content_click` | Какая кнопка приводит к форме и нажимают ли посетители на карточки без действия? `content_click` содержит только разрешённый тип карточки. |
| Форма | `form_start`, `field_focus`, `field_input`, `form_submit_click`, `form_invalid` | Доходят ли до ввода данных и на каком поле возникает ошибка браузерной проверки? `field_input` отмечает только первый ввод в поле, без значения. |
| Исход | `form_submit`, `form_success`, `form_error`, `form_abandon` | Теряются ли заявки до отправки или после ответа сервера? |
| Время | `page_exit` | Сколько длился просмотр; событие может отсутствовать при резком закрытии браузера. |

Для долей воронки используйте `sessions`, а не `hits`: один просмотр может несколько
раз нажать кнопку или ошибиться при заполнении. События показывают действия, но сами
по себе не объясняют мотив бота. Следующую правку стоит выбирать по самому большому
падению между этапами и проверять отдельным прогоном симулятора.

Экспорт пригоден для основных этапов скилла: карта DOM, воронка, сопоставление
конвертированных и неконвертированных траекторий. Он не является записью Webvisor:
нет непрерывного видео, координат мыши и времени чтения отдельных элементов.

В исходном лендинге CTA есть в тарифах, но нет кнопки в первом экране: в таком
варианте значения `hero` для `cta_view` и `cta_click` отсутствуют. Сравнивайте
раскладку формы с исходным прогоном по общей конверсии и по шагам после CTA тарифов.
В текущем совместном варианте CTA первого экрана использует тот же класс
`.btn-register`, регистрируется как `hero` и предлагает базовый тариф. Клики по
карточкам тарифов остаются отдельными значениями `pricing_1`–`pricing_3`.
