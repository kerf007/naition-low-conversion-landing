# Результат переноса формы под первый экран

Версия приложения: `868fd58`. HTML опубликованного сайта полностью совпал с локальным `index.php`. Изменено только положение секции регистрации. План: [form-position-experiment-2026-10-22.md](form-position-experiment-2026-10-22.md).

Источники: [агрегат](behavior-form-position-2026-10-22.json), индивидуальные визиты и серверные счётчики в `data/visits-2026-10-22-form-position/`, лидерборд. Данные сохранены перед следующим Redeploy; контакты из серверного экспорта не сохранялись.

## Итог

| Метрика | Форма внизу | Форма под hero |
| --- | ---: | ---: |
| Визиты | 201 | 202 |
| Заявки по серверу | 56 | 57 |
| Конверсия по серверу | 27,9% | 28,2% |
| Успешные заявки по трекеру | 55 | 57 |
| Клики CTA | 200 | 200 |
| Показ первого поля | 200 | 201 |
| Начало ввода после CTA | 55/200 (27,5%) | 57/200 (28,5%) |
| Начало ввода до CTA / без CTA | 0 | 0 |
| Успех среди начавших | 55/55 | 57/57 |

Разница общей конверсии — +0,36 процентного пункта. Лидерборд показывает 28,2% и первое место на момент проверки. В новом прогоне сервер и трекер согласуются: 57 заявок. В контроле было расхождение на одну заявку, поэтому клиентские и серверные показатели приведены отдельно.

95% интервалы Уилсона: 22,12–34,43% против 22,46–34,79%. Двусторонний точный тест Фишера p=1,0. Наблюдения не дают оснований считать перенос улучшением; они также не доказывают полное отсутствие эффекта. Прогоны последовательные, без случайного распределения вариантов.

## Изменения траекторий

- Все 200 CTA-кликов снова пришлись на hero при scrollY=191. Кнопки тарифов не нажимались.
- В 127 из 200 визитов с CTA первое поле было видно до клика; в 73 — после. Ранее все 200 показов поля происходили после CTA. У ещё одного визита без CTA поле также было видно.
- Все 57 начавших ввод сделали это после CTA. Ранний показ формы не привёл к заполнениям до клика. Это согласуется с гипотезой о заданном порядке действий бота, но не раскрывает его алгоритм принятия решения.
- Медианное время первого показа поля уменьшилось с 44,73 до 20,15 секунды. Медианное время клика CTA — с 43,34 до 42,06 секунды. Медианное начало ввода среди заполнивших стало позже: 50,34 против 47,23 секунды. Показатели рассчитаны для разных групп и не являются индивидуальной разницей задержек.
- Медианное время после CTA увеличилось: среди успешных визитов с 13,18 до 16,80 секунды, среди остальных с CTA — с 6,72 до 10,55 секунды. Укорочение расстояния до формы не ускорило завершение сценария; причина не установлена.
- 143 посетителя нажали CTA, но не начали ввод. Всего 144 увидели первое поле без ввода, включая один визит без CTA.
- У 201 из 202 визитов есть `page_exit`. Один длинный визит без CTA и заявки не завершён в телеметрии: его длительность 328,88 секунды — нижняя оценка. Нельзя уверенно классифицировать его как бота или человека. Другой визит без CTA длился 2,79 секунды и включал четыре клика по программе.
- Ошибок формы, невалидных полей и отказов после начала ввода не зафиксировано. Все визиты отмечены как desktop; мобильный эффект не проверен.

## Вывод

Перестановка секций не сломала наблюдаемый сценарий симулятора: заявки продолжают успешно поступать. Однако рост конверсии от переноса формы этим прогоном не подтверждён. Это подтверждает техническую возможность перестановки, но не позволяет объявить именно это ограничение задуманной автором подсказкой.

Код по итогам анализа не менялся. Дальнейший кандидат для обсуждения — уменьшение обязательного ввода (email и цель курса), поскольку основной отвал остаётся перед заполнением. Сейчас сервер требует оба значения: эксперимент потребует изменения полей и серверной валидации, а также проверки совместимости с ботом. Конкретный вариант следует сначала представить пользователю.
