# Пакет гипотез: программа, тарифы и начало заполнения

## Гипотезы

1. Подробное описание занятий в сворачиваемых модулях позволит одновременно сохранить полноту программы и уменьшить видимую длину страницы.
2. Компактный первый экран и тарифы после вводного раздела помогут раньше увидеть предложение и выбрать участие.
3. Более компактная форма, переход к панели и фокус в имени облегчат начало заполнения.
4. Выбор цели из списка вместо свободного текста уменьшит число действий.
5. CTA после вводного блока и программы дадут дополнительные точки перехода к форме.

Это пакетный эксперимент: результат покажет эффект совокупности изменений, а не вклад каждого пункта. Положительный результат потребуется повторить; он не раскрывает алгоритм симулятора.

## Изменения

- Цена базового курса 3 900 ₽, дата 21 ноября, время 10:00–18:00.
- Порядок: первый экран → о курсе → тарифы → форма → программа с подразделами травм и инструкторов → юридическая информация → фото.
- Шесть основных секций и шесть CTA. Заголовок карточки о практике уточнён до «Однодневный практический курс».
- Шесть подробных описаний программы восстановлены из исходной версии нашего проекта; абзацы содержат 590 слов. Аккордеон закрывается после загрузки JS, без JS подробности остаются видимыми.
- Кнопки аккордеона поддерживают Enter/Space, `aria-expanded`, `aria-controls`; свёрнутое тело имеет нулевую высоту, `inert` и `aria-hidden`. Оно остаётся в DOM, но исключается из дерева доступности. При раскрытии семантика и содержимое возвращаются.
- Три контактных поля в строку на десктопе, цель — обязательный select с начальным значением «Помощь близким». Пользователь может выбрать другую цель.
- После CTA панель центрируется, если помещается в окно; на низких окнах выравнивается по верхнему краю. Фокус переносится в имя с `preventScroll`.
- Сохранены ID/action формы, названия четырёх полей, скрипт регистрации визита и обязательные классы. Обработчик заявки и схема БД не менялись.

## Аналитика

Метки `course-flow-v1` / `price3900-course-flow`, версия схемы `preinput-v1`.

- CTA различаются по источникам `hero`, `about`, `program`, `pricing_1..3`.
- Добавлено `focus_requested` перед программным фокусом. Автофокус не порождает `input` или `form_start`.
- Классификатор выделяет автофокус без ввода/указателя/Tab отдельно. Эта категория не означает самостоятельное намерение посетителя.
- Tab отслеживается после CTA и за пределами формы; значения клавиш ввода и содержимое полей не записываются.
- Select учитывается в обычном трекере и диагностике.
- Экспорт диагностики выдаётся последовательно по визитам, чтобы не держать полный журнал геометрии в памяти PHP.

## Контроль и прогон

Предыдущая версия `0e927f5`: большой прогон, 154 заявки; серверный снимок 502 визита (30,68%), клиентская загрузка 501 визит. События трёх ID без page_view исключены из клиентской когорты; серверный знаменатель не менялся. Сводка: [behavior-program-copy-500-2026-10-24.json](behavior-program-copy-500-2026-10-24.json).

Подробный диагностический экспорт этого прогона не получен: действующая версия сервера исчерпала 128 МБ PHP-памяти при сериализации. Сохранены обычные события, серверные счётчики, диагностическая сводка и текст ошибки. Не интерпретировать отсутствие подробной диагностики как отсутствие препятствий или ошибок.

Новый экспорт проверен на изолированной тестовой БД: 600 визитов, 24 000 событий геометрии, корректный JSON размером 54 877 855 байт при лимите PHP 32 МБ. Тестовая БД удалена после проверки, данные локальных и публичных прогонов не использовались для нагрузочного теста.

После Redeploy нового варианта запустить 500 визитов с прежними настройками, дождаться завершения без остановки по промежуточному проценту. Основная метрика — серверные заявки / визиты; дополнительная — реальный ввод после CTA. Фокус больше не сопоставим с прошлым вариантом как показатель намерения.

Прогоны последовательные, без рандомизации. Сохранить полный архив до следующего Redeploy. Зафиксировать фактический знаменатель и интервалы, не объявлять победу по одному большему проценту.
