# Мгновенный переход к форме: результат прогона

## Результат

Версия `a56d22d`: мгновенный переход CTA вместо плавной прокрутки и новая диагностика до ввода. Цена 3 900 ₽, выделен базовый тариф, четыре обязательных поля.

| Показатель | Предыдущий прогон `3858c95` | Новый прогон `a56d22d` |
| --- | ---: | ---: |
| Серверные визиты | 501 | 102 |
| Заявки | 137 | 30 |
| Конверсия | 27,3% | 29,4% |
| CTA + начало ввода | 137 / 500 | 30 / 100 |
| CTA без начала ввода | 363 | 70 |

Разница +2,07 п.п.; двусторонний точный тест Фишера p=0,716. Интервал Уилсона 95% для новой конверсии: 21,4–38,9%. Рост не доказан; отсутствие значимого различия не доказывает равенство вариантов. Прогоны последовательные, без рандомизации; одновременно с прокруткой добавлен трекер, поэтому его влияние отдельно не измерено.

В интерфейсе запрошено 100 прогонов, сервер зарегистрировал 102 визита. Используем фактический знаменатель, не исключаем два визита по догадке об их происхождении. Снимок лидерборда также показывает 102/30 и третье место.

## Что удалось узнать о потере до ввода

Все 100 CTA были в первом экране. В каждом таком визите зарегистрировано прибытие к форме, последующая прокрутка колесом и возврат к форме. Мгновенный переход не устранил этот маршрут: одной анимацией CTA объяснить его нельзя. Внутренний алгоритм симулятора нам неизвестен.

| Наблюдение по попытке после CTA | Количество |
| --- | ---: |
| Нажатие на поле, фокус, ввод и успешная заявка | 30 |
| Первое поле доступно в последнем снимке, попытки взаимодействия нет | 66 |
| Первое поле менее чем наполовину видно в последнем снимке, попытки нет | 4 |
| Попытка нажать без фокуса / фокус без ввода / ввод без успеха | 0 / 0 / 0 |

Доступность означает: поле видно минимум наполовину, редактируемо, допускает фокус и pointer events, проверенные точки не перекрыты. Это проверка состояния в момент снимка, а не непрерывная гарантия.

У всех четырёх визитов с обрезанным полем ранее были снимки с доступным полем. После возврата к форме они прокрутили страницу дальше; перед уходом поле оказалось выше экрана. Это может быть следствием продолжения просмотра. Причинность «ушёл, потому что поле обрезано» не установлена.

Таким образом, все 70 не начавших ввод имели доступное первое поле хотя бы в одном снимке после CTA. Основная потеря происходит до попытки взаимодействия; массовая механическая невозможность нажать на поле данными не подтверждается. Мотив отказа из этого не следует.

Медиана от последнего зарегистрированного прибытия к форме до фокуса — 0,598 с; до ухода без фокуса — 2,359 с. Это разные группы, сравнение не устанавливает причину. Первое прибытие фиксируется примерно через 0,407 с после CTA: трекер ждёт 400 мс без прокрутки. Это не длительность анимации.

## Качество данных

- Обычная и диагностическая выгрузки содержат одинаковые 102 ID визитов.
- У 100 CTA-попыток есть завершение; пропусков нумерации и срабатываний лимита записи нет.
- Два визита без CTA: один завершён, второй без события ухода. Они включены в общий знаменатель, но не в классификацию CTA-попыток.
- Клиентский успех совпал с сервером: 30. Ошибок отправки и валидации не зарегистрировано.
- Все визиты имеют desktop-телеметрию. Выводы о мобильных отказах невозможны.
- Все диагностические записи имеют `preinput-v1` / `3858c95-instant`.
- Сохранённые публичные HTML/CSS/JS совпали с локальным коммитом `a56d22da691bef03201ce19918491fcbdf3a56e5`.

## Решение и следующие гипотезы

1. Не считать мгновенную прокрутку победившим вариантом и не тратить следующий прогон только на повтор этой гипотезы без расчёта требуемой выборки.
2. Приоритет — условия, по которым симулятор решает начинать ввод: содержание и компактность программы/предложения. Это гипотеза о точке принятия решения, не установленный алгоритм. Ранее самый большой прирост сопровождался сокращением программы и изменением информации о тарифе; эффекты этих правок по отдельности неизвестны.
3. Следующий опыт должен изолировать один фактор на текущей стабильной версии, с той же диагностикой и фиксированными ценой, формой и CTA. Например, менять только компактность блока программы при неизменном тексте, чтобы отделить влияние геометрии от содержания. Сначала локально проверить, что меняется именно задуманный фактор.
4. Не использовать автофокус как доказательство устранения отказа: он искусственно увеличит число фокусов. Основной результат — серверная заявка; промежуточный — реальное начало ввода после CTA.

Новых изменений лендинга по итогам этого анализа не внесено. Обновлены архив результата и локальный дашборд.
