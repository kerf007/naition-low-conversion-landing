# Диагностика до первого ввода: подготовка прогона

Обновление: по решению пользователя к следующему прогону добавлена [гипотеза мгновенного перехода к форме](instant-scroll-experiment-2026-10-23.md). Ниже описана исходная подготовка измерений.

## Контроль и область изменения

Контроль — `3858c95`: базовый курс 3 900 ₽, выделена базовая карточка, четыре обязательных поля; последний результат **137/501 = 27,3%**. Экспорты сохранены до нового деплоя.

В интерфейсе лендинга не менялись тексты, цена, CSS, поля, их обязательность и обработка заявки. В `index.php` добавлена загрузка диагностического скрипта; в `js/main.js` — защищённые вызовы диагностики CTA, запроса прокрутки и успешной отправки. Сам диагностический код не вызывает прокрутку, фокус и изменение DOM. Дополнительное измерение всё же может влиять на время выполнения; следующий прогон проверяет и работу измерения.

## События и данные

`js/form-diagnostics.js`, версия `preinput-v1`, отправляет пакеты в `diagnostics.php`:

- CTA с отдельным номером попытки, собственный запрос прокрутки, остановка после 400 мс без scroll-событий, прибытие и повторный возврат к форме.
- Повторные геометрические экспозиции формы, описания тарифа, каждого поля и submit. Для формы достаточно пересечения, для поля/описания — не менее 50%. Экспозиция заканчивается при уходе из viewport или скрытии вкладки; сохраняется её длительность.
- Нажатие на поле/подпись, нажатие в прямоугольнике поля с фактической целью вне формы (например, перекрытие), фокус, уход из поля, первое input каждого поля на попытку, Tab/Shift+Tab, wheel/touchmove с ограничением частоты.
- Геометрия после CTA, при устойчивой остановке около формы, взаимодействии, скрытии вкладки и выходе. Координаты, видимая доля, пять hit-test точек, disabled/readonly, focusable, pointer-events для полей, подписей, описания, кнопки и формы.
- Размеры layout/visual viewport, масштаб, видимость вкладки, разрешённый ID активного поля, факт начала ввода, порядок событий, время от открытия страницы.
- `tracker_version=preinput-v1`, `ui_version=3858c95`, `experiment_id=price3900-diagnostics`; ui_version обозначает неизменённую конфигурацию интерфейса, а SHA деплоя фиксируется отдельно при выгрузке.

Обычные события `behavior.php` сохранены. Оба журнала используют один случайный session ID, поэтому их можно соединить по visitId. С серверной таблицей заявок нового общего ID пока нет.

## Хранение и ограничения

Отдельная таблица `form_diagnostics` в том же временном SQLite-файле `/tmp/naition-behavior-v1.sqlite`. При Redeploy данные могут сброситься, поэтому сохранять оба экспорта до деплоя.

- Пакет максимум 8 событий и 64 KiB; события максимум 240 на сессию, 12 CTA-попыток, до 16 обычных снимков геометрии плюс финальный снимок. Превышения отмечаются `capture_limited`.
- Идемпотентная запись по `(session_id, seq)`; сервер проверяет строгую схему, численные диапазоны и конечные списки типов/ID.
- Значения полей, текстовые клавиши, буфер обмена, HTML и скриншоты не собираются. Признак input_started относится к действию, а не содержимому.
- Пакетирование не гарантирует доставку при закрытии вкладки или перегрузке keepalive-очереди. Пропуски seq, отсутствие завершения и ограничения учитываются как неизвестность.
- Проверка видимости и hit-test — наблюдение в момент снимка. Она не гарантирует непрерывную доступность и не определяет намерение посетителя. Определение scroll_settled — эвристика покоя, а не сигнал внутреннего решения бота.

## Экспорты и панель

- `GET /diagnostics.php` — счётчики диагностических событий.
- `GET /diagnostics.php?format=visits` — хронология и снимки по визитам.
- Сохранить индивидуальный экспорт как `data/visits-<название-прогона>/diagnostics.json` вместе с обычными серверными счётчиками и `behavior.php?format=visits`.
- Локальная панель `http://127.0.0.1:8787/` автоматически находит такие локальные экспорты через «Обновить из файлов». Старые прогоны не получают вымышленных диагностических событий.
- Для командной строки: `python3 -B tools/metrics_dashboard/diagnostics.py <путь-к-экспорту>`.

В панели появились отдельные категории CTA-попыток: успех; ввод без успеха; фокус без ввода; нажатие без фокуса; доступно в последнем снимке без попытки; препятствие в последнем снимке; скрытая вкладка; неизвестность. Несколько CTA одного визита считаются несколькими попытками и не подменяют серверную конверсию.

## Проверки

- PHP lint, JavaScript syntax checks, `git diff --check`.
- Шесть unit-тестов классификации: неизвестная видимость, пропуск seq, клавиатурный фокус без pointerdown, повторный CTA, перекрытие/скрытая вкладка, лимит измерения.
- Локально в браузере воспроизведены: успешная заявка, форма без действий, фокус без ввода, подавление установки фокуса после pointerdown, перекрытие, скрытая вкладка (симуляция visibilityState), уход вниз и возврат, повторный CTA.
- На восьми исходных локальных сценариях получены девять CTA-попыток и ожидаемые категории без пропусков seq; значения введённых данных в диагностическом экспорте отсутствуют.
- Сервер отклоняет неизвестное поле `state.value` и недопустимый seq; повторная доставка не добавляет запись.
- Стресс из 300 синтетических focus-событий достиг лимита; потеря части пакетов обнаруживается по seq и классифицируется как неизвестность. Полная доставка при таком стрессе не заявляется.
- При блокировке диагностического endpoint локальная заявка успешно отправляется.
- Панель проверена с пустым архивом и подставным тестовым агрегатом, в том числе на 390 px. Тестовый агрегат не сохранён в историю реальных прогонов.

## Следующий прогон

Redeploy и 200 визитов с прежними настройками. Сначала проверить полноту обоих журналов и совпадение session ID, затем распределение наблюдаемых ветвей. Выгрузить серверный экспорт без контактных значений, оба обычных отчёта и новый диагностический экспорт. До анализа не менять цену и интерфейс.
