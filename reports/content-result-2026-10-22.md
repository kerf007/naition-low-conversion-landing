# Результат: короткая программа и состав тарифа у формы

Проверенная версия приложения: `07ba6c5`. На опубликованной странице есть сокращённая программа и состав тарифа; опубликованные JS и CSS совпадают с локальной версией по SHA-256.

Источники: [агрегат поведения](behavior-content-2026-10-22.json), локальные индивидуальные экспорты в `data/visits-2026-10-22-content/`, серверный `api/export.php` (сохранены только счётчики и технические метаданные), лидерборд. Экспорты сохранены до следующего Redeploy. План: [content-experiment-2026-10-22.md](content-experiment-2026-10-22.md).

## Итог

Серверная конверсия выросла на 14,5 процентного пункта, примерно в 2,08 раза. Лидерборд независимо показывает 201 визит, 56 заявок, 27,9% и первое место на момент проверки 22 октября 2026.

## Проверка полноты данных

В сервере 56 разных идентификаторов заявок. Повторное чтение подтвердило 56 заявок против 55 клиентских `form_success`. У всех 201 клиентских визитов есть `page_exit`; ошибок формы, невалидных полей и бросания после начала ввода не зарегистрировано. Пропущенная клиентская отправка либо заявка вне наблюдаемого клиентского сценария остаются возможными объяснениями. Причину установить нельзя: экспорт сервера не содержит общего с трекером идентификатора визита. Нельзя автоматически относить дополнительную заявку к одному из 145 визитов без ввода.

Поэтому общую конверсию считаем по серверу, а переходы внутри воронки — по трекеру. Даже консервативное сравнение 55/201 против 27/202 показывает крупный рост.

## Что изменилось в поведении

- До CTA не дошёл 1 посетитель вместо 27. Единственный короткий визит длился 2,79 секунды, закончился в программе и включал четыре клика по её информационным карточкам. Отсутствие указателя-руки само по себе не устранило такие клики.
- Все 200 CTA-кликов снова пришлись на hero после просмотра других секций и возврата к первому экрану; scrollY при клике всегда 191 px. Кнопки тарифов не нажимались. Сценарий по-прежнему выглядит автоматизированным, а роль подтверждения разных тарифов не проверена.
- Медианное время до CTA сократилось с 46,28 до 43,34 секунды. Типичная высота страницы снизилась примерно с 8 318 до 7 705 px (около 613 px, 7,4%). Это соответствует гипотезе об облегчении пути, но не доказывает конкретный механизм симулятора.
- Начало ввода после видимости формы выросло с 15,4% до 27,5%. Это второй источник улучшения, помимо роста числа дошедших. Его нельзя приписать только составу тарифа: одновременно изменились программа и геометрия страницы.
- Основная оставшаяся потеря — 145 визитов с показом формы без начала ввода. Все 55 начавших заполнили четыре поля и получили успех.
- Медианное время после CTA: у заявившихся 13,18 с (раньше 13,19), у не заявившихся по трекеру 6,72 с (раньше 7,07). Длительность заполнения почти не изменилась.
- Все текущие визиты имеют viewport height 720 и событие `page_view: desktop`. Эффект мобильной версии этим прогоном не измерен. `program_view` отсутствует; прохождение секции нельзя интерпретировать как чтение текста.

## Надёжность и следующий шаг

95% интервалы Уилсона: контроль 9,35–18,75%, новый вариант по серверу 22,12–34,43%. Двусторонний точный тест Фишера даёт p≈0,00034 (по клиентским успехам p≈0,00051). Это сильный наблюдаемый сдвиг, но прогоны последовательные, без случайного распределения вариантов; одновременно проверен пакет из трёх изменений.

Рекомендация: сохранить `07ba6c5` как лучший измеренный вариант. Для учебного отчёта уже есть полный цикл «наблюдение → гипотезы → пакет правок → измеренный результат». Если нужен дополнительный прогон, сначала повторить эту же версию для проверки устойчивости; менять код перед ним не требуется. Любой дальнейший пакет сначала представить пользователю для просмотра. Новые правки приложения по итогам анализа не вносились.
