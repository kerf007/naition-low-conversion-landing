# Гипотеза: мгновенный переход к форме

## Основание

В последнем прогоне 137/501 = 27,3%, из 500 нажавших CTA 363 не начали ввод. После CTA все 500 проходили нижние секции и возвращались к форме. Это не доказывает, что обход вызван плавной прокруткой приложения: поведение может задаваться симулятором. [Анализ](pre-input-analytics-plan-2026-10-23.md).

Проверяем: мешает ли движение страницы после CTA доступности формы или следующему действию. Гипотеза — мгновенный переход позволит раньше получить устойчивую позицию формы и повысит вероятность начала ввода.

## Изменение

Только переход четырёх CTA к секции регистрации меняется с `behavior: 'smooth'` на `behavior: 'instant'`. `auto` не подходит: на странице задан `html { scroll-behavior: smooth; }`.

Цена 3 900 ₽, выделение базовой карточки, четыре обязательных поля, тексты, расположение секций и CSS сохранены. Автофокус, автоматическое заполнение и отправка заявки не добавляются. Прокрутка по другим ссылкам и действия самого симулятора этой правкой не управляются.

Одновременно используется новая диагностическая аналитика из `2b79ded`. Маркеры: `tracker_version=preinput-v1`, `ui_version=3858c95-instant`, `experiment_id=price3900-instant-scroll`. Сборщик также принимает прежнюю пару маркеров для уже открытых страниц; при анализе разделять варианты.

## Критерии

Основные: серверная конверсия и начало ввода / CTA относительно контроля 137/501. Диагностические: CTA → остановка у формы, повторные уходы и возвраты, доступность поля в снимках, нажатие без фокуса, фокус без ввода.

- Если на мгновенном переходе остаётся дальнейший обход страницы, одна анимация нашего CTA не объясняет весь маршрут.
- Если поле стабильно доступно, а посетители по-прежнему не пытаются взаимодействовать, гипотеза о технической задержке теряет приоритет.
- Рост конверсии вместе с нормальной доступностью будет основанием для повторной проверки, но не докажет механизм: новые измерения вводятся в том же прогоне, а сравнение последовательное.

Исторических данных о новых событиях нет: не заменять их отсутствие нулём и не выдавать новое время остановки за точное сравнение с прежней диагностикой.

## Запуск

Локально проверены все четыре CTA при ширине 390 и 1280 px: сразу после обработчика верх секции регистрации находится на y=0, тарифы подставляются корректно, фокус не переносится в поле, горизонтального переполнения нет. Диагностический сервер принял события с новой парой маркеров, включая scroll_settled. PHP lint, JavaScript syntax checks и `git diff --check` прошли.

Redeploy финального коммита, затем 200 визитов. Если прогон предыдущей версии уже начат, сначала завершить и выгрузить его; не менять код посреди прогона. После завершения сохранить серверные счётчики, `behavior.php`, `behavior.php?format=visits` и `diagnostics.php?format=visits`.
